# Adapter — gentle-ai

How the overlay binds to gentle-ai's real, documented seams. The core (`VISION`, `PHASE-LENS`) is
host-agnostic; only this file knows gentle-ai. If a gentle-ai update changes a seam, only this file
changes.

## Seams we depend on

| Seam | What it is | How the overlay uses it |
| --- | --- | --- |
| Project `AGENTS.md` | gentle-ai reads it as the project activation boundary | **Primary injection point.** The installer adds the overlay activation block here. |
| Skill registry (`.atl/skill-registry.md`) | auto-generated index; the orchestrator injects matching `SKILL.md` paths into each subagent | **Read-only for us.** Install places both `intent-overlay` and `clean-code-standards` in scanned skill roots so the registry indexes and injects their `## Compact Rules`. We do NOT write the registry — it is regenerated by `gentle-ai skill-registry refresh --force`. |
| Engram SDD topics (`sdd/{change}/...`) | per-phase artifacts persisted across the chain | The intent lives in SDD's own `proposal`/`spec`/`design` topics; phases read the approved proposal and write their `Intent Gate` line. No separate intent artifact. |

> **Why not the registry?** It carries an `Auto-generated` header and is rebuilt from scanned skill
> directories. A manual row would be erased on the next refresh. `AGENTS.md` is durable and reversible,
> so it is the single wiring point.

## What the installer writes to AGENTS.md

A single marker-delimited block (idempotent, reversible):

```
<!-- intent-overlay:start -->
## Intent Overlay (active)

Govern every substantial SDD change with one approved intent and one quality bar — no extra documents.
The intent lives in SDD's own `proposal`/`spec`/`design`; the human approving the proposal is the
freeze. Trivial or small changes skip SDD: apply clean-code judgment inline and stop.

Pass these overlay paths to EVERY SDD phase, and apply them through `overlay/skill/references/PHASE-LENS.md`:
- `overlay/skill/references/VISION.md`
- `overlay/skill/references/PHASE-LENS.md`

Every phase emits `Intent Gate: aligned | drift-detected`. Code phases also emit the Clean Code Gate
at refactor-exit. `drift-detected` halts the chain and returns to the human as a change request (a
proposal amendment); it is never applied silently.
<!-- intent-overlay:end -->
```

## Commands

- `install.sh install [DIR]` — add the block to `DIR/AGENTS.md` (default: current dir). No-op if present.
- `install.sh uninstall [DIR]` — remove the block, leaving the rest of `AGENTS.md` byte-identical.
- `install.sh doctor [DIR]` — verify the seams: `AGENTS.md` exists and is writable, the overlay docs
  exist, and `clean-code-standards` is present in the registry. Non-zero exit if a seam is missing.
- `install.sh --direct` — standalone mode (no host). **Deferred in v1**: prints a not-implemented notice.
